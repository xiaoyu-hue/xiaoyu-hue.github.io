时念:把最私密的记录,交给一把自己做的锁

2026-10-11 · 项目故事 · shinian
本地优先端侧加密Capacitor安全审计

这个项目是从一扇窗开始的,最后长成了一个关于"信任"的问题。它叫时念(ShiNian),一句话概括是"活着的窗景:天空随时刻与四季流动的时间工具"。但我想讲的重点不是那扇窗,而是窗后面锁着的东西。

起因:我只是想要一扇跟着时间走的窗

起点很简单。v0.1.0 那版(2026-10-04)只有四样:一个按真实时刻分钟级插值变色的天空引擎、一层液态玻璃的界面、一个时钟,和倒数日的增删改查。

然后我一层一层往上加:天气改成由真实的日出日落时刻驱动(不是拍脑袋定的几点变亮),数据来自 Open-Meteo,配 57 个城市可选;季节层用"四立"节气做切换点——立春、立夏、立秋、立冬,而不是公历季度的分界线,前后还留了七天渐变;四季各有彩蛋,春樱飘落、夏夜萤火虫、秋天落叶、冬夜极光;再后来是常驻流星,和一座许愿池。

这些是很感性的东西,做起来也最花时间。但做到许愿池那一步,我忽然意识到一个问题:倒数日里记着谁的生日,许愿池里写的是真心话。这些东西,我不想让它们裸奔。

它现在长什么样

截至 v1.1.3(2026-10-08),它同时有三种形态,共用同一套内核:

  • 浏览器直接访问,是网页版;
  • 把 index.html 下载下来双击就跑,是零构建本地版——不需要 Node.js,不需要装任何东西;
  • 装在手机上,是Android APK,用 Capacitor(把网页打包成手机应用的工具)封装,发布态还会过一遍 javascript-obfuscator 混淆。

TypeScript 源码经 esbuild 编译打包,每次改动都要过 13 套 211 项测试和类型检查。最近一轮甚至把物理天空色算了进去:用 Rayleigh 和 Mie 单次散射算真实的大气颜色,CPU 上采样 16×8,再和手工调好的"艺术锚点"按三成比例融合——物理负责准,手调负责好看。

我拍板的三个决定

1. 加密保险库做进软件,但网页端默认不锁

核心是一把主密码加密保险库:AES-GCM-256 加密数据,PBKDF2-SHA256 迭代 21 万轮从你的密码派生密钥。真正的 DEK(数据加密密钥)永不落盘。手机上还能用生物识别,由系统 Keystore 封装这把 DEK,验证通过才解出来。

但网页端的加密开关,默认是关的。不是忘了开——关着的时候软件和刚打开时一样用过就能上手,零门槛;你打开它,才需要设主密码,并把已有的明文数据一条条迁进去、删掉明文副本。手机 App 那边则是强制开启、不可关闭。

这个取舍的代价我必须自己说出来:默认关,就意味着绝大多数网页访客的数据仍然是明文。这是在"别把人吓跑"和"默认就该安全"之间做的选择,我选了前者,并且如实写进了文档——没有用一句笼统的"已加密"把它糊过去。

2. 免费的安全审计,我选了"全部都上"

GitHub 原生的三件套——CodeQL(代码语义分析)、Dependabot(依赖漏洞)、Secret Scanning(密钥泄漏,还配了自定义正则保护主站域名和 API 令牌)——全部启用。之外又叠了三件:Gitleaks(专门翻历史里有没有泄漏的密钥)、Semgrep(多语言语义规则,含 OWASP 前十风险的规则集)、MobSF(对安卓包做静态加动态混合分析,对标移动应用安全标准 MASVS)。

关键是它们全部跑在 GitHub Actions 的免费额度上,零上云。这一点对我很重要:一个标榜"零采集"的项目,不能为了做安全审计,转头把代码送到别人的服务器上去。

3. 混淆和自检只是抬高门槛,不是上锁

发布态的代码会混淆。App 里还有一层 WebView 自检,检测从最初的 4 类扩到 6 类:除了调试器和运行环境,还查Frida、Xposed 这类注入框架的痕迹,以及核心加密层有没有被人替换或挂钩;探针从一次改成三次;命中高危时直接阻断。

但有一件事我主动没做——原生级的运行时防护(RASP)没有引入。评估后放弃了 Free-RASP 这样的方案:它的上报机制和这个项目的"零采集"隐私基调冲突,而且原生目录不入库,我没法在本地真的验证它。于是文档里明确标注:原生级防护未引入,WebView 层已经做到我能想到的最大化。

一个差点让数据永久消失的 bug

这一段我最想留下来。v1.1.0 刚把"明文迁到加密"做完,二次审查就翻出一个要命的问题:原来的迁移逻辑是异步落盘 + 立刻删明文 + 吞掉错误。

这意味着什么?加密还没真正写进去,明文就已经被删了,而写入失败的错误被静默吞掉。结果是——数据永久消失,没有任何提示。

修法是把顺序反过来:逐条写入,各自等到落盘确认之后才删对应的明文;写入失败必须向上抛出,不许再吞。附带还堵了一处投降式的降级:加密已就位时,写入不允许再悄悄退回明文——那是一条隐私契约,不能在看不见的地方失守。

这不是用户报上来的,是我们回头审查自己翻出来的。教训很朴素:凡是"删除不可恢复的数据"加上"依赖异步写入"的组合,都必须等到确认。否则你删掉的很可能就是唯一的副本。

诚实清单:它做不到什么

  • 双击版没有加密层 — file:// 打开时根本没有安全层,开关自动隐藏,数据是明文
  • 网页端默认不加密 — 多数访客的数据仍是明文,要不要锁由你自己决定
  • 没有原生级反篡改 — WebView 自检到不了原生层的深度
  • 混淆挡不住有决心的人 — 它抬高的是门槛,不是天花板
  • 天气依赖外部接口 — 断网时会静默降级为上一次的有效数据,不是实时
  • 节气依赖第三方农历库 — 库缺失时回退到按公历月份近似
  • 云的形态还没做完 — 分形边缘和多尺度细节侵蚀被明确列进下一版,不是遗留口头承诺

回过头看

写 Nymir 那篇时我说过一句:一个不会写密码学的人,能做出加密的功能,但做不出信任。时念是同一道题,只是离得更近——这里面放的是我真的会在意的东西。

我能做的只有一件事:把每一处"我做不到什么",写得比"我做到了什么"更清楚。因为对这样一个装念想的地方来说,最重要的从来不是它有多少层保护,而是你敢不敢把真话放进去。
