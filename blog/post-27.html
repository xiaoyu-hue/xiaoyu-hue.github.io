书时:让读书变成一件有牵挂的事

2026-10-22 · 项目故事 · tailtale
游戏化阅读本地优先PWA无支付

这是第七个作品,也是第一个"玩起来"的作品:书时 TailTale,一个游戏化阅读器。玩法一句话能说完——读书记时长金币,金币养宠物。这篇文章想讲三件事:这个闭环是怎么设计的、我拍板了哪几个决定、以及它现在还做不到什么。

起因:想让读书这件事本身有牵挂

前面六个项目都是工具:管事情的、管信息的、管时间的。书时想换一个角度——不去"管理"阅读,而是让阅读本身变得有牵挂。

它的产品原则写在 PRD 里,一共四条:本地优先、零成本运营、游戏化驱动、克制。阅读是核心场景,宠物是情感招牌,工具箱是增值配件。数据全部不出浏览器,没有服务器、没有数据库、没有账号;AI 功能用 BYOK(用户自带密钥)模式,运营成本为零。

它现在长什么样

从 v0.1.0(10-14 初始提交)到 v1.7.0(10-22),八天里发布了八个正式版本,路线图上的 M1~M3、M5、M6 均已上线,只剩 M4 工具箱和 M7 作品化:

  • 书架:导入 TXT / EPUB / PDF,想读 / 在读 / 读完三状态,按文件内容指纹(SHA-256)记忆进度,同一本书换设备能续读;
  • 阅读器:TXT 章节自动拆分、EPUB 流式分页(epub.js)带 CFI 精确续读、PDF 按页渲染(pdf.js)大文件懒加载;三个阅读器统一的滑动翻页手势,iOS 与安卓都真机验证过;
  • 游戏化:打开书籍即计时,切浏览器后台自动暂停,刷新后续计时;阅读每 30 分钟 +10 金币,每分钟 +1 XP,每日打卡 +5 起,读完一本书 +100;
  • 宠物:一只像素猫,饱食度 / 心情 / 精力三属性按天衰减,好感度与成长值分离,四档成长阶段;连续阅读 30 分钟,它会蹭屏幕撒娇;
  • AI 解读书:BYOK 模式,浏览器直连 DeepSeek,生成全书大纲或针对这本书提问,调用前预估费用;
  • 打磨:液态玻璃 / 像素风两套皮肤、浅色 / 深色主题、数据一键导出导入备份、73 项单元测试。

我拍板的几个决定

1. 金币只能赚,不能买

游戏化产品最常见的设计就是内购。书时反过来:金币只能靠阅读赚取,不可购买。没有支付功能,就没有商户资质、没有支付合规的问题,也没有"不充值就玩不下去"的设计压力。商店是金币的唯一出口——四件零食,即买即用。

这个决定的代价也很直白:它大概率赚不到钱。但书时的定位就是开源作品,无支付、无商业化,这一点从 PRD 定稿那天起就没变过。

2. 宠物不会饿死

电子宠物最容易踩的坑就是"死亡机制"——几天不打开,宠物死了,用户干脆就不回来了。书时的设计是无死亡机制:饱食度低只是好感度下降,猫会"表示想念",但永远活着。离线衰减按时间戳差分结算,一次最多结算 7 天,防止设备长期关机造成属性断崖。

连带的是防刷设计:好感度每日获取上限 +10;睡觉中不能互动,堵住挂机刷属性的口子;计时单 tick 增量上限 5 秒,防睡眠唤醒虚增。

3. 皮肤免费,不做成商品

PRD 原稿里"阅读主题皮肤"是 300 币的商品。做到 M6 时我改了主意:液态玻璃和像素风两套皮肤免费一键切换。原因很实际——皮肤的吸引力应该来自"好看",而不是"攒了多久";把 UI 个性化的门关卡在金币后面,劝退的比留下来的多。猫皮肤(橘猫 / 三花 / 黑猫)保留在金币体系里,等"商店"模块建成后再接入。

4. AI 用 BYOK,不碰用户密钥

AI 解读书没有走"平台代付"模式,而是 BYOK:用户自己申请 DeepSeek 密钥,存在浏览器本地,代码里不存在上传或传输密钥的逻辑。换来的是零 AI 运营成本,代价是每位用户都要自己填密钥——这个门槛我接受,因为它同时也是一条隐私边界。

诚实清单:它做不到什么

  • 数据只在浏览器里 — 清除浏览器数据前必须先导出备份,否则阅读记录、金币、宠物一起消失
  • AI 解读首期只支持 TXT / EPUB — PDF 暂不支持;密钥与调用费用由用户自担
  • 工具箱还没上线 — 番茄钟 / 白噪音 / 文本统计 / 书摘导出 / 今日一书还在 M4 计划中
  • 设置键暂无迁移机制 — localStorage 不像 IndexedDB 有迁移登记,未来改设置键名,老用户的设置可能静默丢失
  • 依赖较新的浏览器 — 需要近两年版本的 Chrome / Edge / Safari(依赖 IndexedDB 与 Service Worker)
  • 不提供书源 — 不内置、不索引任何盗版书源,导入文件的来源合规责任在用户自己

回过头看

书时是七个项目里第一个"游戏"。它让我确认了一件事:非程序员能做的不只是"工具",还可以是"玩的东西"。金币闭环、宠物衰减、防刷策略这些听起来很"产品"的东西,一样是在 AI 的协助下,由一个不会写代码的人拍板做出来的。

当然,它现在也只是一个开始——M4 工具箱、M7 作品化(README、demo、公版书库)都还在路上。那句老话照样算数:代码是 AI 写的,判断是我做的。
